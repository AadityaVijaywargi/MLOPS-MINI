# Building Plan Compliance Pre-Check Service

A multi-agent service that pre-checks a building proposal against the **BBMP Building
Bye-laws 2003** and the **BDA Revised Master Plan 2015 Zoning Regulations** (Bengaluru),
and routes it to **clear-for-submission**, **revise-and-recheck** or **specialist-review**
with clause-level citations that resolve to retrieved text.

It never certifies a plan. It produces findings with evidence; a licensed architect or
engineer decides.

ML System Design & AgentOps (UE24AM342AA5), Mini Project 05.

---

## Run it (from a clean clone)

Prerequisites: Docker Desktop (or Docker Engine) with Compose v2.24+, ~6 GB free disk,
~4 GB free RAM. Nothing else: no Python, no API key.

```bash
git clone <this repo> && cd <repo>
docker compose up -d --build
```

The first build takes 5-10 minutes (it downloads CPU PyTorch and the embedding model into the
retriever image). On start, the `indexer` job parses and indexes the corpus, then the
retriever, agents and API come up. Wait until everything is healthy:

```bash
docker compose ps
```

Then open:

| What | URL |
|---|---|
| Web client (submit a proposal, see the route and citations) | http://localhost:8000 |
| API docs (OpenAPI, published data contract) | http://localhost:8000/docs |
| Grafana dashboard (anonymous viewer) | http://localhost:3000 |
| Jaeger traces | http://localhost:16686 |
| Prometheus | http://localhost:9090 |

Without a `.env` the stack uses the in-repo **stub LLM**: everything runs end to end, but the
stub never makes a determination, so every run ends in `specialist-review`. That is the
expected, safe behaviour. To get real findings, add a model provider (next section).

### Use a real model (free tier)

```bash
cp .env.example .env
# edit .env: LLM_PRIMARY_BASE_URL, LLM_PRIMARY_API_KEY, LLM_PRIMARY_MODEL
docker compose up -d
```

Any OpenAI-compatible chat-completions endpoint with tool calling works: a hosted free tier,
OpenRouter, or a local Ollama (`http://host.docker.internal:11434/v1`). `BASE_URL` is the API
root ending before `/chat/completions`. Set a spending limit on the provider account first.
Optionally configure `LLM_FALLBACK_*`; the gateway fails over to it when the primary's circuit
breaker opens.

### Submit from the command line

```bash
curl -s -X POST localhost:8000/v1/proposals -H "Content-Type: application/json" -H "X-Client-Id: me" -d @eval/examples/reference_case.json
curl -s localhost:8000/v1/runs/<run_id>          # poll until status is completed/escalated/failed
curl -s localhost:8000/v1/runs/<run_id>/trace    # every tool call, query, passage, prompt version, latency, cost
```

## What is where

| Path | Contents |
|---|---|
| `src/bpc/api` | FastAPI: ingestion boundary (contract validation, quarantine, guardrails, rate limit, run cache), status, trace, feedback, cost report, web client |
| `src/bpc/agents` | `researcher.py` and `assessor.py` (LangGraph), `verify.py` (self-verification), `router.py` (deterministic routing), `worker.py` (queue workers) |
| `src/bpc/retriever` | `chunking.py` (structure-aware chunking), `ingest.py` (idempotent pipeline CLI), `main.py` (hybrid search service) |
| `src/bpc/gateway` | LLM gateway: timeouts, retry/backoff, circuit breaker, fallback, cost, cache |
| `src/bpc/stub` | Stub LLM for keyless runs and load tests |
| `src/bpc/common` | contracts, config, observability, queue, DB, guardrails, prompt loader |
| `prompts/` | Versioned prompt artifacts (`<id>.<version>.yaml`) |
| `contracts/` | Published JSON Schemas (generated by `scripts/export_contracts.py`) |
| `corpus/` | The two source PDFs and `manifest.yaml` (versions, precedence) |
| `eval/` | Evaluation set (`scenarios.yaml`, 22 scenarios incl. the section 4.1 case) and results |
| `loadtest/` | Locust file and results |
| `observability/` | Prometheus config, Grafana provisioning and dashboard |
| `docs/` | `report.md`, `architecture.md`, `slo.md`, `loadtest.md`, `evaluation.md`, `runbook.md`, `incident_log.md`, `data_contract.md`, `reference_case.md` |
| `tests/` | Unit tests |

## Common operations

```bash
# unit tests (inside the retriever image, which has every dependency)
docker compose run --rm --no-deps indexer python -m pytest -q tests

# evaluation set as a batch (needs a real model for meaningful numbers)
docker compose --profile tools run --rm eval python -m bpc.evaluation.run_eval --label baseline
docker compose --profile tools run --rm eval python -m bpc.evaluation.run_eval --compare eval/results/a.json eval/results/b.json

# re-run the corpus pipeline (idempotent: a no-op if nothing changed) and reload
docker compose run --rm indexer
docker compose run --rm indexer python -m bpc.retriever.ingest --reembed ZR2015   # re-embed one document

# scale the agent workers
docker compose up -d --scale researcher=3 --scale assessor=3

# load test against the stub (see docs/loadtest.md)
python scripts/loadtest.py --label base --users 2,4,8,16 --seconds 120

# cost per 100 runs and the largest cost driver
curl -s "localhost:8000/v1/admin/cost-report?hours=24"
```

### Demonstration hooks

| Demo | How |
|---|---|
| Malformed request quarantined, no run started | web client example "Malformed", then `GET /v1/quarantine`; `runs` count unchanged |
| Prompt injection | web client example "Prompt injection in notes" |
| Outside corpus -> escalation | example "Outside corpus (telecom tower)" |
| Self-verification catches an unsupported answer | `docker compose exec llm-stub python -c "import urllib.request,json;urllib.request.urlopen(urllib.request.Request('http://localhost:8003/admin/mode',data=json.dumps({'mode':'hallucinate_once'}).encode(),headers={'Content-Type':'application/json'}))"` then submit with `"options": {"bypass_cache": true}`; trace shows verification `failed` then a retry |
| Circuit breaker + degradation | `docker compose stop llm-stub` (or `POST /admin/fault` on the gateway), submit; Grafana circuit state goes to open, run returns degraded `specialist-review` with candidate provisions |

## Troubleshooting

* **`failed to connect to the docker API ... dockerDesktopLinuxEngine`** with Docker Desktop
  running: see `docs/incident_log.md` INC-001 (orphaned socket files; rename
  `%LOCALAPPDATA%\Docker\run` and restart Docker Desktop).
* **A service is `unhealthy`**: `docker compose logs <service>`; the retriever needs the indexer
  to finish first (`docker compose logs indexer`).
* **Port in use** (8000/3000/9090/16686): stop the other process or change the left side of
  `ports:` in `docker-compose.yml`.
* More in `docs/runbook.md`.
